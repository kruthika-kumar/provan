# Shiproom pilot runbook

Prepare a disposable local clone, bind a release brief, and use only declared read-only capabilities. Keep credentials outside Shiproom artifacts. Record PM, EM, and Measurement usefulness, false positives/negatives, setup friction, duration, harness/model provenance, and limitations. Hardening triage is limited to P0 trust and P1 usability failures. Do not publish or select a real pilot repository through this workflow.

## Ordered local workflow

1. Capture the disposable clone's HEAD, tracked-file set, release state, Product Intent,
   graph, assessment, and Measurement/AI generation hashes.
2. Run remediation-roadmap prepare/compile/show, review-plan prepare/show/render-package,
   contestation show, and management-artifacts compile/show. These operations are packet-only.
3. Optional specialist work is returned only through issued inbox contracts; record transport,
   declared capability, permission, and independence limitation. A reviewer is not an owner
   without existing release-bound owner authority.
4. PM, EM, Measurement, and owner review the local reports; record evidence-authority errors,
   report/remediation/contestation usefulness, false positives, false negatives, setup time,
   duration, and limitations.
5. Clean up the disposable fixture. Triage only P0 trust and P1 usability changes.
